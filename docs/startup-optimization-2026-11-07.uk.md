# Оптимізація початкового завантаження

7 листопада 2026 року. Зміни виконано локально, без коміту, push або публікації. Це наступний етап після [оптимізації ресурсів і прокручування](performance-review-2026-11-07.uk.md).

## Що змінилося

Спільний `app.scss` тепер збирається в кешований глобальний CSS після `styles.scss`, замість рядка всередині JavaScript. Порядок і самі правила оформлення збережено.

Contact і анкета Podcast винесені в окремі standalone-компоненти через `@defer`. Код попередньо завантажується у вільний час браузера або при наведенні/фокусі кнопки; форма створюється лише після відкриття. Після закриття компонент знищується й очищає поля. Збережено вибір мережі, ліміти, галочки, розтягування textarea та повернення фокуса. Для повільного завантаження й помилки є вікна того самого стилю з можливістю закриття, Escape та обмеженням переходів Tab усередині вікна. Показ стану завантаження починається лише після 150 ms, без обов'язкового затримування готової форми.

Прямі візити до `/privacy/`, `/legal/` і `/podcast/terms/` отримують пререндерені HTML/CSS без Angular bootstrap, event replay, transfer state і script preloads. Збережено всі стилі, scoped-атрибути, метадані, JSON-LD, `noscript` і звичайні посилання. CSS-loader `print + onload` перетворено на звичайне завантаження CSS. Прямі сторінки використовують повну навігацію браузера; перехід із головної через Angular і далі працює з lazy-компонентами.

Обробка виконується через npm `postbuild`. Для хостингу потрібно використовувати `npm run build:hosting`: прямий `ng build` оминає цей хук. Перевірка зупиняє збірку при появі інтерактивних елементів або непідтримуваних дій на цих трьох сторінках. Майбутні функції, яких немає в SSR-розмітці, також потребують ручного перегляду цього списку. Cloudflare може додавати свій RUM після збірки; локальний сервер діагностики додає власний probe. Тому відсутність Angular app JS не означає відсутність усіх можливих скриптів хостингу.

## Розмір збірки

Порівняння локальних production-файлів до й після цього етапу:

| Показник | До | Після |
| --- | ---: | ---: |
| Головний `main` JS-файл | 44 291 B | 17 037 B |
| Увесь заявлений початковий JavaScript головної | 306 270 B | 285 510 B |
| Той самий JS, Brotli | 84 159 B | 80 951 B |
| HTML головної | 32 692 B | 24 119 B |
| Inline CSS у головній | 24 062 B | 15 444 B |
| Початкові JS + зовнішній CSS, raw | 307,02 kB | 309,72 kB |
| Початкові JS + зовнішній CSS, оцінка Angular | 84,91 kB | 85,93 kB |

Початковий JavaScript зменшено на **6,8%** без стиснення. Зменшення `main` на 61,5% не слід подавати як зменшення всього JavaScript на стільки ж: частина спільного коду міститься в інших початкових chunks. Після винесення CSS і додавання механізму відкладених форм початковий сумарний JS/CSS трохи більший. Мета — менше JavaScript для обробки на старті, окреме кешування стилів і відсутність запуску Angular на прямих інформаційних сторінках. Idle-prefetch також означає, що сумарні байти за весь сеанс не обов'язково менші.

Відтворити звіт про розміри: `node scripts/measure-startup.mjs`. Він враховує entry scripts, modulepreloads та їхні статичні imports; динамічні й idle-prefetched chunks не входять у його початкову суму. Це розміри файлів, а не замір швидкості фізичного телефону чи передавання через Cloudflare.

## Перевірка

- Фінальний `npm test -- --watch=false`: **22 тести успішні**, 5 тестових файлів, включно зі станами завантаження/помилки, фокусом, Escape та закриттям до завершення deferred load. Перший повторний запуск зупинився до виконання тестів через Windows `EPERM` при перейменуванні файлу у системному temp; успішний запуск використовував `TEMP`/`TMP` у `tmp/vitest-startup-final` всередині проєкту. Виробничий код заради цього не змінювався.
- Production-збірка й `check:hosting` успішні: 5 пререндерених маршрутів, 50 файлів. Для трьох інформаційних сторінок перевіряється відсутність Angular scripts/preloads і доступність нативних посилань.
- Порівняння обчислених стилів головної, Podcast і обох готових форм із попередньою збіркою не виявило відмінностей у перевірених розмірах, шрифтах, відступах, фонах, тінях та заокругленнях.
- На всіх трьох інформаційних сторінках стилі прямого статичного відкриття збігаються з переходом через Angular. Нативні кнопки-посилання Back працюють.
- Браузерні перевірки 390×844 і 320×568: горизонтального переповнення немає; поля введення зберігають 16 px; на короткому екрані форма прокручується всередині обмеженого вікна. Вибір Instagram, закриття Escape, повернення фокуса та очищення анкети при повторному відкритті працюють.
- У переглянутому браузерному сеансі немає console error/warn. Це локальна перевірка, без імітації процесора та мобільної мережі; вона не встановлює гарантованих LCP/INP для всіх відвідувачів.

Надсилання повідомлень і заявок на пошту не підключалося: обидві форми залишаються локальними preview, як до оптимізації.

Механізм відкладених компонентів описано в [документації Angular 21](https://v21.angular.dev/guide/templates/defer).
