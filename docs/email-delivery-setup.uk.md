# Доставка форм на пошту

Підготовлено для `syohtimofey.com` 7 листопада 2026 року. Наявність реалізації в Git не означає, що надсилання вже активоване на опублікованому сайті: потрібні налаштування нижче й deployment цього коду. Фактичну доставку після налаштування потрібно перевірити тестовими листами.

Contact і анкета Podcast надсилають запит до Cloudflare Pages Function. Після перевірки полів і Turnstile функція передає лист у Resend для доставки на `timofeysyoh@gmail.com`. Email відвідувача міститься у Reply-To, тому звичайна кнопка «Відповісти» адресує відповідь йому. Автоматичний лист відвідувачу не надсилається.

## 1. Підготувати Resend

1. Створіть обліковий запис у [Resend](https://resend.com/).
2. У **Domains** додайте `syohtimofey.com`. Якщо виберете окремий піддомен для листів, адреса відправника теж має належати підтвердженому піддомену.
3. У DNS Cloudflare додайте саме ті записи DKIM/SPF та інші записи, які покаже Resend. Не замінюйте наявний SPF навмання й не додавайте другий SPF для того самого імені: узгодьте записи з уже підключеними поштовими сервісами.
4. Дочекайтеся статусу **Verified**.
5. У **API Keys** створіть ключ для надсилання листів; за можливості обмежте його цим доменом.

Адреса відправника для цієї конфігурації — `forms@syohtimofey.com`. Resend дозволяє надсилати з адрес підтвердженого домену; окрему Gmail-скриньку з такою назвою створювати не потрібно. Отримувачем залишиться `timofeysyoh@gmail.com`. [Підтвердження доменів](https://resend.com/docs/dashboard/domains/introduction), [ключі API](https://resend.com/docs/dashboard/api-keys/introduction).

## 2. Підготувати Turnstile

У Cloudflare відкрийте **Turnstile**, створіть widget і виберіть режим **Managed**. Додайте hostname `syohtimofey.com`; `www.syohtimofey.com` додавайте лише якщо сайт справді доступний на ньому. Збережіть **Site key** і **Secret key** для наступного кроку. Не вмикайте довільні hostnames для production.

Форма завантажує перевірку лише при надсиланні. Компактний widget може показати додаткову перевірку, якщо це потрібно Cloudflare. Сервер перевіряє токен, hostname і дію форми; одного зображення widget у браузері недостатньо. [Налаштування widget](https://developers.cloudflare.com/turnstile/get-started/widget-management/), [серверна перевірка](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).

## 3. Додати змінні у Pages

Відкрийте **Workers & Pages → ваш Pages-проєкт → Settings → Variables and Secrets → Add** («Налаштування → Змінні та секрети → Додати», якщо ці назви перекладені у вашому інтерфейсі). Виберіть production-середовище.

| Ім’я | Значення | Тип |
| --- | --- | --- |
| `RESEND_API_KEY` | Ваш справжній ключ Resend | Secret / Encrypt |
| `FORM_FROM_EMAIL` | `forms@syohtimofey.com` або адреса підтвердженого піддомену | Text |
| `FORM_TO_EMAIL` | `timofeysyoh@gmail.com` | Text |
| `TURNSTILE_SITE_KEY` | Site key створеного widget | Text; публічний ключ |
| `TURNSTILE_SECRET_KEY` | Secret key того самого widget | Secret / Encrypt |

Для секретів виберіть **Encrypt**, потім **Save**. Вставляйте їх безпосередньо у Cloudflare; у репозиторії є лише `.dev.vars.example` без робочих значень. Production і Preview мають окремі налаштування. Не копіюйте production-секрети до Preview без потреби; для нього потрібні свої дозволені hostnames і усвідомлена перевірка доставки. [Змінні та секрети Pages](https://developers.cloudflare.com/pages/functions/bindings/).

## 4. Опублікувати через наявне підключення Git

Після локальних перевірок у Pages мають залишитися:

| Налаштування | Значення |
| --- | --- |
| Root directory | Корінь репозиторію |
| Build command | `npm run build:hosting` |
| Build output directory | `dist/syohtimofey/browser` |
| Node.js | `24.14.0`, із `.node-version` |

Тека `functions/` повинна бути в корені репозиторію поруч із `package.json`; не переносіть її у `dist`. Cloudflare збирає Functions окремо від статичних файлів. `public/_routes.json` обмежує виконання функцій маршрутами `/api/*`, а звичайні сторінки залишаються статичними.

Після додавання змінних потрібен новий deployment. Коміт і push виконуються окремим погодженим кроком; ця підготовка їх не виконує. Звичайне перетягування ZIP у Dashboard Direct Upload не підтримує Functions; використовуйте поточну інтеграцію Git або Wrangler. [Розгортання Pages Functions](https://developers.cloudflare.com/pages/functions/get-started/).

## 5. Перевірити доставку після deployment

1. Відкрийте `https://syohtimofey.com/api/forms/config`. Готова конфігурація повертає `available: true` і публічний Site key, без секретів. Недоступна — `available: false` зі статусом 503; це не підтверджує надсилання.
2. Надішліть одну тестову контактну форму й одну тестову анкету подкасту з власними даними та позначкою «Тест» у повідомленні.
3. Перевірте результат на сайті, записи відправлення Resend, «Вхідні» та «Спам» Gmail. Статус прийняття листа сервісом не гарантує потрапляння до «Вхідних».
4. Перевірте кнопку «Відповісти»: отримувачем має бути email із тестової форми.

Повідомлення про помилку не означає, що жоден сервіс не отримав запит: збій може статися під час відповіді. Закриття форми також не відкликає вже отриманий сервером запит. Обробник використовує ключ ідемпотентності для повторної спроби тієї самої заявки; це не замінює перевірку фактичної доставки.

## Локальна робота

`npm start` запускає Angular UI без Pages Functions; локальний діагностичний сервер також віддає тільки статичні файли. Для повного локального середовища можна скопіювати `.dev.vars.example` у локальний `.dev.vars`, заповнити свої значення, зібрати сайт і запустити з кореня:

```sh
npm run build:hosting
npx wrangler pages dev dist/syohtimofey/browser
```

Якщо Wrangler не встановлено, `npx` запропонує отримати офіційний пакет із npm. Для реального Turnstile та локальної доставки потрібні відповідні дозволені hostnames і коректні ключі. Не використовуйте production-конфігурацію для автоматичних тестів, які можуть надіслати справжні листи. Автоматичні перевірки реалізації використовують підміни зовнішніх API.

Політику `/privacy/` оновлено для умовно ввімкненої доставки через Cloudflare, Resend і Gmail. Перед прийманням анкет перевірте налаштування акаунтів, доступ до пошти й фактичні строки зберігання відповідно до вашої діяльності. Анкета подкасту не є автоматичним бронюванням або дозволом на запис.

## Виконані локальні перевірки

- `npm run test:functions`: 19 серверних тестів успішні. Перевірено валідацію, обмеження JSON, Origin, honeypot, Turnstile action/hostname, відсутність надсилання при відмові перевірки, Reply-To, сталий ключ повторної спроби та відповіді Resend. Зовнішні API підмінені.
- `npm test -- --watch=false`: 31 тест успішний у 6 файлах. Перевірено обидві форми, стани надсилання, повторні натискання, збереження полів після помилки, повторні спроби та скасування роботи при закритті. Для запуску використано локальні `TEMP`/`TMP` у `tmp/vitest-email`, оскільки Windows-пісочниця обмежує системну тимчасову теку.
- `npm run build:hosting`: перевірка типів Functions, production-збірка, статична оптимізація та hosting checks успішні; 5 сторінок, 51 файл. Обидва серверні endpoints додатково зібрані esbuild для середовища без Node.js API.
- Локальна браузерна перевірка 390×844 з реальним handler конфігурації та порожніми bindings: обидві форми коректно показують недоступність доставки, залишають поля й дозволяють повторну спробу. Горизонтального переповнення немає; Turnstile-скрипт у недоступній конфігурації не запитується, console error/warn не зафіксовано.

Під час цих локальних перевірок секретів не додавали й реальних листів не надсилали. Адреса отримання та контакт у Privacy оновлені на `timofeysyoh@gmail.com`. Фактичну доставку через Resend у Gmail потрібно перевірити після налаштування й deployment.
